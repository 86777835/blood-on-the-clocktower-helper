# 2026-11-04 · 调研：魔典支持自定义剧本和自定义角色（只调研，不写代码）

工作目录是 `血染钟楼助手/`。开始前先读 `README.md`、`docs/调研清单.md`（里面有已经定好的合规做法：免费、标明非官方、能力文字自己写、规则助手不下定论）、`docs/游戏信息.md`，并浏览 `public/` 下的角色数据和魔典逻辑，了解现在支持哪些剧本和角色，以及数据是怎么组织的。

## 用户要问的
> 研究一下血染钟楼魔典能加自定义剧本和角色吗
> 只有自定义剧本能加自定义角色

也就是说，官方的三个剧本不允许加自定义角色；自定义角色只能出现在用户自己导入或创建的自定义剧本里。

## 需要调研并回答的问题（要联网查，每条结论附来源链接）
1. **TPI 的政策**：TPI 的社区内容政策（Community Created Content / fan content policy 之类）对下面两件事怎么规定：
   - 第三方工具支持“自定义剧本”；
   - 第三方工具支持“自定义角色（homebrew）”。
   请说明有哪些限制，例如能不能用官方的角色名、能力原文、图标，能不能收费，需要标注什么。还要查中文版（集石，“染·钟楼谜团”）有没有额外的规定。
2. **剧本数据格式**：
   - 官方 Script Tool（script.bloodontheclocktower.com）导出的 JSON 是什么格式：`_meta` 有哪些字段，角色 id 的写法，自定义角色对象支持哪些字段（如 id、name、team、ability、image、firstNight/otherNight、firstNightReminder、reminders、setup、jinxes 等）。
   - 社区常用工具（clocktower.online、botcscripts.com 等）用的是不是同一种格式。
   - 中文圈（集石、中文 App 或小程序、中文剧本分享站）的剧本格式能不能对接，角色 id 和中文名怎么对应。
3. **官方角色数据从哪来**：自定义剧本通常会用到全部官方角色（含实验性角色、旅行者、传奇角色，总共大约 170 多个），而我们站现在只做了 72 个。请查清：
   - TPI 的 botc-release 仓库（我们的图标就是从这里来的）或其他官方开放渠道，有没有开放角色数据，包括能力文字、夜晚顺序、提醒标记，以及中文版本。授权条款是什么，我们能不能用。
   - 如果官方只开放了图标，没开放能力文字，那么补齐其余角色有哪些办法，各自的工作量和合规风险是什么。我们的做法是能力文字自己写。
4. **对我们魔典的影响**：自定义剧本会影响哪些现有功能？请逐项说明“能直接复用 / 需要改 / 做不到”：
   - 按人数分配阵营数量；
   - 改变配置的角色（例如男爵 +2 外来者，对应 JSON 里的 setup 标记）；
   - 夜晚顺序清单；
   - 提醒标记；
   - 相克规则（jinx）；
   - 现有的“真实信息”自动计算：只认识官方角色，自定义角色应该怎么处理；
   - 隐藏信息过滤：自定义角色的阵营怎样影响谁能看到什么；
   - 发身份；
   - 玩家手机上的剧本表；
   - 复盘和存档。
5. **自定义角色（只在自定义剧本里）的设计建议**：
   - 用户需要填哪些字段，最少要填什么；
   - 图标怎么处理：上传图片、外链 URL（安全风险）、还是用文字和颜色代替；
   - 剧本怎么保存和复用：只存在当前房间，还是存一个个人或公共的剧本库（存在哪里，要不要审核）；
   - 怎么防止有人借自定义角色传播不当内容。
6. **其他工具参考**：已有工具（clocktower.online、官方 App、中文工具）怎么处理自定义剧本和自定义角色，用户评价怎样。

## 用户补充（调研开始后收到）

> 就是说书人可以选择自建自定义板子，然后名称啊、角色啊这些从池子里随便配

也就是说：主要形式是站内的“剧本编辑器”，说书人自己起名字，从角色池里随意挑选角色；导入 JSON 是次要入口。自定义角色只能在自定义剧本里新建。

> 当然也可以自定义角色进去，自己打字输入名称和技能等关键词，还有行动顺序啊这些

也就是说：自定义角色由说书人手动填写，包括名称、阵营、能力描述（关键词）、首夜和其他夜晚的行动顺序（插在官方夜晚顺序的哪个位置），以及提醒标记。
