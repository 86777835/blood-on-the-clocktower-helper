## 用户的要求（原话）
> 就是说书人可以选择自建自定义板子，然后名称啊、角色啊这些从池子里随便配
> 当然也可以自定义角色进去，自己打字输入名称和技能等关键词，还有行动顺序啊这些
> 只有自定义剧本能加自定义角色

用户已定：第一版只用现有的 72 个官方角色（**不补**其他官方角色）。其余采用调研报告的建议：
- 自定义剧本停用“真实信息”自动计算，改成说书人手动记录；
- 自制角色用文字图标；
- 不做图片上传，不做公共剧本库。

## 范围（第一版）
1. **剧本编辑器**（说书人开局时在“剧本”这一步进入）
   - 新建自定义剧本：填剧本名（必填）、作者（可选），然后从角色池里勾选角色。角色池 = 现有的 72 个官方角色，按镇民、外来者、爪牙、恶魔分组，可以搜索。
   - 实时显示每个阵营选了几个，并按本站现有的人数配置规则提示能不能开局，比如某个阵营的角色不够分配时要提示。只提示，不替用户改。
   - 内置的三个剧本（暗流涌动、黯月初升、梦殒春宵）**不能编辑**。在内置剧本上点“复制为自定义剧本”，会生成一个新的自定义剧本再编辑，内置剧本保持原样。
2. **自定义角色**（只能在自定义剧本里新建或编辑）
   - 字段：名称（必填）；阵营（镇民、外来者、爪牙、恶魔，必填）；能力描述（必填，用户自己写，可以写关键词）；首夜行动顺序、其他夜晚行动顺序（可以不行动；行动的话，要能选择插在本剧本夜晚顺序里哪个角色之前或之后）；提醒标记（可以有多个，短文字）；“会改变开局配置”的勾选项（勾上后在配置处给说书人一句人工提醒，不自动计算）。
   - 显示上明确标记为“自制”，用文字图标表示：取名称首字，配上阵营颜色，再加一个“自制”小标。
   - 服务端必须拒绝往内置剧本里加自制角色。只在 UI 上挡住不够，伪造的请求也要拒绝。
3. **导入 / 导出**
   - 导出：把当前的自定义剧本导出成官方 Script Tool 兼容的 JSON，包括 `_meta`（名称、作者）、官方角色 id、自制角色对象。
   - 导入：粘贴或选择 JSON 文件。官方角色 id 映射到我们的 72 个角色；我们没有的官方角色，或者不认识的 id，要**明确列出来，并拒绝导入或让用户选择移除**，不要悄悄丢掉或替换。
   - 格式不对、重复 id、超大文件（设置合理上限）、自制角色和官方角色 id 冲突等情况，都要给出具体的报错。
   - 导入的内容一律当作纯文本处理：不执行，不当 HTML 渲染，不加载其中的任何 URL。
   - 先支持英文官方格式，中文格式先不支持，但要在报错里提示。
4. **对局里的行为**
   - 房间保存的是这一局的**剧本快照**：剧本之后再改，已经开的局和存档里的复盘都不受影响。
   - 夜晚顺序清单按快照生成，官方角色和自制角色一起排序；提醒标记和相克（如果有）照常显示。
   - 自定义剧本的局停用“真实信息”自动计算，那些框改成说书人手动记录。界面上说明为什么停用。官方剧本的局保持原样。
   - 玩家手机上的剧本表显示这套自定义剧本的公开内容：角色名、能力、阵营分组、自制标记。
   - 隐藏信息规则不变：玩家拿不到袋子里有哪些角色、谁是什么身份、标记、说书人笔记等，跟现在一样。
5. **复用**：最近用过的自定义剧本存在说书人本机（localStorage），方便下次再用；也可以通过 JSON 文件分享。
